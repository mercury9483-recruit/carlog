# 차계부 (carlog)

개인 차량 정비 이력·교체 주기·로드맵을 관리하는 웹앱입니다.

```
폰/PC 화면 (index.html, GitHub Pages)  →  Apps Script (apps-script/Code.gs)  →  구글 스프레드시트
```

- 화면은 단일 파일 `index.html` (바닐라 JS, 모바일 우선, 하단 5탭: 홈·입력·이력·비용·로드맵)입니다.
- 데이터는 구글 스프레드시트에만 있고, 이 저장소에는 **개인 데이터와 웹 앱 주소를 넣지 않습니다.**
- 웹 앱 주소는 기기마다 처음 한 번만 입력하며, 그 기기 브라우저(localStorage)에만 저장됩니다.

## 저장소 구성

| 경로 | 역할 |
|---|---|
| `index.html` | 화면 전체. 이 파일이 소스이자 배포 파일입니다. GitHub Pages가 루트에서 서빙합니다. |
| `apps-script/Code.gs` | 구글시트를 읽고 쓰는 Apps Script API. `SPREADSHEET_ID`는 자리표시자입니다. |
| `.gitignore` | 시드 데이터·엑셀·데모 파일이 실수로 올라가지 않게 막습니다. |

## 데이터 시트 (구글 스프레드시트)

| 구분 | 시트 | 내용 |
|---|---|---|
| 기준(마스터) | `M_차량`, `M_정비항목`, `M_업체` | 차량 정보, 정비 항목과 교체 주기, 업체 |
| 이력(트랜잭션) | `R_정비이력`, `R_주행거리`, `R_세금보험`, `R_사고` | 발생할 때마다 한 줄씩 누적 |
| 스냅샷 | `S_항목현황` | 항목별 마지막 교체·다음 예정을 수식으로 집계 |
| 계획 | `P_로드맵` | 1만km 단위 정비 계획 |

- 시트 시간대는 **서울**로 두세요. 다르면 D-day가 하루 어긋날 수 있습니다.
- `ID`, `항목코드` 열은 수정하지 마세요. `S_항목현황`은 수식 시트라 직접 입력하지 않습니다.
- 항목을 추가하려면 `M_정비항목` 맨 아래에 새 코드(E27…)로 한 줄 추가합니다.

## 설정 방법

1. 위 시트 구성으로 구글 스프레드시트를 만듭니다.
2. script.google.com에서 새 프로젝트를 만들고 `apps-script/Code.gs`를 붙여 넣습니다. `SPREADSHEET_ID`를 시트 주소의 ID로 바꿉니다.
3. `testRead`를 한 번 실행해 권한을 승인합니다. (스프레드시트 파일 보기·수정 권한. 코드는 지정한 시트 ID만 읽고 씁니다.)
4. **배포 → 새 배포 → 웹 앱** (실행 사용자: 나 / 액세스: 모든 사용자)으로 배포하고 `/exec` 주소를 복사합니다.
5. GitHub Pages(Settings → Pages → Branch: main / root)를 켭니다.
6. 폰·PC에서 화면 주소를 열고 **연결 설정**에 웹 앱 주소를 붙여 넣거나, 주소 뒤에 `#u=<웹 앱 주소>`를 붙인 링크를 한 번 엽니다. 오른쪽 위에 "구글시트 연결됨"이 보이면 성공입니다.

## 수정·배포

- **화면**: `index.html`을 수정하고 `main`에 올리면 Pages에 반영됩니다. 웹 앱 주소는 바뀌지 않습니다.
- **API**: `Code.gs`를 수정한 뒤 Apps Script에서 **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**로 갱신합니다. '새 배포'를 누르면 주소가 바뀌니 주의하세요.
- API 주소는 공유하지 마세요. 주소를 아는 사람은 데이터를 볼 수 있습니다.

## 계산 규칙 요약

- 교체 시점은 km 주기와 개월 주기를 각각 계산해 더 임박한 쪽으로 판단합니다.
- 일평균 주행거리는 날짜가 기록된 주행거리 지점(주행거리·정비이력·세금보험)에서 구하고, 예상 도래일에 사용합니다.
- 로드맵 항목은 정비이력의 `로드맵ID`로 연결하면 완료 처리됩니다.
- 정비 입력 시 주행거리가 현재 기록보다 크면 `R_주행거리`에 자동으로 한 줄이 추가됩니다.
